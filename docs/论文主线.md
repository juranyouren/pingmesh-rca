# 论文主线：根因排序驱动的故障传播图恢复

> **当前有效口径（2026-09-02）**

本文的主要任务是恢复故障传播图。系统首先定位最可能的根因候选，再在候选根因条件下恢复从根因到 Pingmesh 异常端点的设备级有向传播图。

## 1. 问题背景

Pingmesh 能够发现源端和目的端之间的丢包或时延异常，但不能直接观测异常在数据中心网络内部的起点和传播过程。物理拓扑、异步告警、设备日志和事件时间只能提供间接证据。

单独输出根因设备排名不能回答异常如何扩散；脱离根因恢复传播图又会产生大量方向不明确的候选路径。因此，本文采用显式两阶段结构：先缩小根因空间，再以根因作为传播方向和根可达约束恢复传播图。

## 2. 系统主线

```text
Pingmesh 异常 + 原始 task_topo + 告警/事件
                     ↓
Stage 1：PC-STGR 根因候选排序
                     ↓
             Top-K 根因及概率
                     ↓
Stage 2：P0 根因条件传播图恢复
                     ↓
根因 + 设备传播 DAG + 证据与替代路径
```

### Stage 1：Root Location

PC-STGR 将设备、事件、物理邻接、异常路径位置和事件时间构造成路径条件时空图，输出 case 内的根因 Top-K 排序。Stage 2 默认保留 Top-5，而不是只使用 Top-1，以降低根因误判造成的不可恢复错误。

### Stage 2：Graph Rebuild

P0 是本文当前主方法。它为每个物理相邻设备对汇总正向传播支持、反向传播支持和无直接传播支持，归一化为三状态证据分布。随后针对每个 Top-K 根因，只保留沿根因距离向外、得到足够证据支持的方向边，并在原始拓扑、根可达、症状覆盖和 DAG 约束下恢复传播图。

系统利用传播图解释质量与 Stage-1 分数对 Top-K 根因进行最终排序，但这种重排不改变“先根因候选排序、再传播图恢复”的任务结构。

## 3. 方法角色

- **P0：本文方案。** 确定性证据归一化 + 根因条件 DAG 解码，不使用传播图标签训练边概率。
- **P4：优化模型。** 使用传播图标注训练三状态边分类器，并通过 fold 内验证集选择高精度边接纳阈值。P4 在超过 P0 前不作为论文主结果。
- **P1：退出当前实验矩阵。** 固定权重 Logit/Softmax 不再运行和报告。
- **异构 V0：历史原型。** 不定义当前论文主线。

## 4. 核心论点

本文的关键论点是：根因排序提供传播起点和方向条件，而拓扑、时间与告警证据决定候选传播边；通过根因条件化和全局结构约束，可以把局部旁证转化为一张拓扑合法、根可达、无环且可核验的故障传播图。

## 5. 贡献表述

1. 将 Pingmesh 诊断定义为“根因定位驱动的故障传播图恢复”，主要输出从根因到异常症状的设备传播 DAG；
2. 设计 PC-STGR 根因 Top-K 排序，避免仅依赖 Top-1 的硬串联错误；
3. 设计 P0 三状态证据归一化与根因条件传播图解码，在原始物理拓扑、传播方向、根可达和无环约束下恢复传播图；
4. 建立统一的端到端评测，同时报告 Root Location 与 Graph Rebuild 指标，并通过 P4 监督模型研究传播边学习的改进空间。

## 6. 评价口径

根因定位报告 Top-1、Top-3、Top-5、MRR，以及传播图重排后的最终根因准确率。

传播图恢复报告有向边 Precision/Recall/F1、节点 Precision/Recall/F1、严格完全匹配率、拓扑合法率、DAG 合法率和根可达率。所有学习模型使用 incident-grouped OOF 结果；推理阶段不得读取根因或传播图标签。

统一入口为 `scripts/run_full_experiment.sh`，主结果为 P0，P4作为优化对照。根因定位和传播图恢复指标统一写入顶层 `summary.json` 与 `summary.csv`。
