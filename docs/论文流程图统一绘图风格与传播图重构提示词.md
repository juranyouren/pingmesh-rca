# 论文流程图统一绘图风格与两阶段传播图恢复提示词

## 1. 固定视觉风格

使用适合 INFOCOM/NSDI/SIGCOMM 论文的黑白单线工程示意图。背景纯白，主体使用深灰描边和黑色文字；低饱和蓝色表示观测与证据，低饱和紫色表示根因候选概率，低饱和橙色强调最终传播图。模块采用轻圆角矩形，主流程自左向右。避免渐变、阴影、3D、卡通图标和大面积填色。

全图只展示两个主阶段：`Stage 1 Root Location` 与 `Stage 2 Graph Rebuild`。P0必须标为 Stage 2 的论文方法；P4只能出现在虚线优化分支；不展示P1和异构 V0。

## 2. 方法总览图提示词

Create a publication-ready black-and-white monoline system diagram for a data-center-network paper. Arrange the content from left to right as observed inputs, Stage 1 root location, Stage 2 graph rebuild, and final outputs. Use muted blue for observed evidence, muted purple for root probabilities, and muted orange for the selected propagation graph.

On the left, show three input groups: “Pingmesh Symptom Context”, “Raw task_topo Physical Topology”, and “Alarms, Logs, and Timestamps”. Do not depict observation relations as known causal edges.

Stage 1 is “PC-STGR Root Location”. Inside it, show a compact path-conditioned Device–Event graph encoder and a case-wise root scoring head. Its output must be an ordered “Top-K Root Candidates” list with probability bars. Clearly show that Top-K, not only Top-1, is passed downstream.

Stage 2 is “P0 Root-Conditioned Graph Rebuild”. Show a root-independent physical candidate graph with three local evidence states for each adjacent device pair: “A→B Support”, “B→A Support”, and “No Direct Support”. Then show one branch per Top-K root candidate. Each branch applies “Outward from Root”, “Raw-topology Valid”, “Root Reachable”, “Acyclic”, and “Symptom Covered” constraints before producing a candidate propagation DAG.

Show a compact final scoring block that combines “Normalized Stage-1 Root Score” and “Graph Explanation Score”. If graph evidence is insufficient, show a small fallback arrow labeled “Keep Stage-1 Order”.

On the right, make the selected orange Device→Device DAG the main visual object. Mark its source as “Final Root”. Attach small evidence badges or blue links to alarms/events. Include result fields “Directed Propagation DAG”, “Evidence Trace”, “Alternative Root-conditioned Graphs”, and “Diagnosability”.

Add a thin dashed side branch from the local edge-evidence block labeled “P4 Supervised Optimization (OOF)”. It replaces only P0 edge probability estimation and rejoins before the same root-conditioned decoder. Label it “validation-selected threshold and No-Direct margin”. Do not draw P4 as the main method.

The figure must communicate the explicit order: root candidate ranking first, propagation graph reconstruction second. Every final edge is constrained by raw physical topology. Timestamps, alarm semantics, and adjacency are circumstantial evidence, not confirmed causality.

## 4. 推荐图注

**根因排序驱动的 Pingmesh 故障传播图恢复框架。** 系统首先利用 PC-STGR 从 Pingmesh 异常、物理拓扑和设备事件中生成 Top-K 根因候选；随后，P0对物理相邻设备的正向、反向和无传播证据进行归一化，并在每个候选根因条件下施加传播方向、原始拓扑、根可达、无环和症状覆盖约束，恢复候选传播 DAG；最后结合根因概率和图解释质量选择最终根因—传播图。P4仅作为共享解码器上的有监督边概率优化分支。

## 5. 复核清单

1. 全图必须只有 Stage 1 与 Stage 2 两个主模块；
2. PC-STGR Top-K 是 Stage 2 的显式输入；
3. P0是主方法，P4只能作为虚线优化分支；
4. 不出现P1或异构 V0；
5. 最终设备传播 DAG 是主视觉对象；
6. 所有最终边均可回溯到原始 `task_topo`；
7. 不把时间先后、拓扑邻接和告警语义画成确定因果；
8. 图中同时展示 Stage-1 分数与图解释分数；
9. 展示证据不足时回退到 Stage-1 排序；
10. 输出保留替代根因条件图与诊断状态。
