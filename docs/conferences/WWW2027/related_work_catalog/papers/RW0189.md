## 1. 论文解决的问题

大规模云基础设施中**严重网络故障引发的告警洪水**。多源告警按时间与位置构造
**层次告警树**，结合流量/用户信息评估故障范围与严重度，使用**设备连接图**与告警投票
给出定位辅助信息。

## 2. 与 RPG-Recon 的重叠

- **已构建层次告警树与设备连接图**；区别在于其图边主要表示**已有连接**，
  而本文推断**故障实例中的直接影响方向**。
- §7.3 的案例说明：设备硬件错误日志可能**晚于** BGP 断链、丢包、不可达告警出现。
  这支持 C1/C2 中「最早告警不一定对应根因」的动机。
  **注意**：这是**该论文的案例证据**，不是本项目数据集上已完成的统计观察——
  引用时必须这样表述。

## 3. 与本文的关键不同条件

- **输出**：incident 分组、范围、严重度、定位辅助信息；**不是**可逐边评价的传播 DAG。
- 仓库选型决定：只取其在告警投票机制作**轻量定位对照**，命名
  **SkyNet-inspired Alert Voting**，**不称完整 SkyNet**。
- 其原始输出不足以支持 Oracle-Graph / Full-Graph 列，相应单元格固定为 `X`。

## 4. 可能的审稿质疑（对我方）

1. 「SkyNet 已在 SIGCOMM 2025 讨论云网络故障的告警影响传播，你的新意？」
   ——输出对象与评价目标不同：告警树/范围/严重度 vs 设备级有向传播图。
2. 「SkyNet 已有设备图，你说的图有何不同？」——其边表示**已有连接**，
   我方推断**本次事故的影响方向**；须在正文明确此区别。
3. 若引用 §7.3 的「硬件日志晚于网络告警」作为动机，必须注明是**他人案例证据**，
   不能暗示本项目数据已观察到同样规律。
