## 1. 论文解决的问题

分布式系统中服务互相依赖，故障会**传播并引发级联失败**；要定位性能退化根因，
构造**服务依赖图**很有价值。但复杂路由（尤其是 **NAT**）会掩盖真实主机，
使被动观测网络元数据的方法推断失败。

## 2. 方法与输出对象

一个运行时系统，构造**进程级服务依赖图**：
- **无需源码插桩**；
- 对 NAT 等复杂路由保持稳健；
- 通过在 TCP 包头**非破坏性注入元数据**，在跨主机时保持协议正确性；
- 部分部署时，若接收端无 agent，则不影响既有 TCP 连接。

**输出对象：进程级依赖图。**

## 3. 与 RPG-Recon 的重叠与关键差异（**T007 R3 的核心更正**）

**该文没有提供「未观测依赖不计错」的掩码先例。** T007 首轮把该文写成
「显式排除未观测边/不算错」，**这是把原文处理写反了**。

原文 §VI-A 的实际内容：
- 参考拓扑包含**架构上定义的全部潜在服务关系**；
- 架构上存在但**运行期无流量**的依赖，工具**发现不了**，因此 **recall / F1 下降**；
- 原文只是**解释为什么指标低**，**没有**核实到作者把这些边从分母中排除。

因此：
- 不能把 A4 当作 masked evaluation 的先例；
- 必须区分**「已知存在、但观测窗内未出现的边」**与**「真值尚未判定的关系」**——
  两者不能自动使用同一个掩码；
- 我方的 unknown / allowed 掩码设计，应标明是**本项目建议**并说明评测目标，
  而不是「沿用他人做法」。
