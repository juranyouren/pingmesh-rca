## 1. 论文解决的问题

电信/云/微服务系统在组件故障时产生**关联告警级联**。RCA 的目标是找出每次级联中真正
的**起始告警**（少量）。常见做法是从观测日志学一个因果图，再预测每个 incident 子图中
**入度为零**的告警。问题是：学到的图是固定的，无法利用历史事故的专家诊断来改进。

## 2. 输入与额外观测要求

- 观测：告警日志（题名、资源、时间）。
- **额外要求**：一个**带标签的对齐集**（labeled alignment set），标签形式是
  「哪些告警应当是源节点」。这是监督信号，属于本方法的核心输入条件。
- LLM 用于**生成候选图编辑**（离线改进阶段）；测试时不再调用 LLM。

## 3. 方法与输出对象

用 LLM 提出语义上合理的图编辑（加/删/改边），由确定性代码校验节点身份与**无环性**，
并在带标签对齐集上保留最优图。迭代该「提议—校验—选择」闭环。

**输出对象：一张精化后的因果图**；测试时仅用该图产生预测，因此预测可解释且不依赖
LLM 调用。这是一个明确的**图结构输出**方法。

## 4. 节点 / 边 / 时间尺度

- 节点：**告警类型 / 告警事件**（TeleRCA 含 194 种告警类型、5,621 个资源）。
- 边：告警之间的因果关系（有向，要求无环）。
- 时间尺度：摘要未给出时间窗与滞后定义 ⇒ **UNKNOWN**。

## 5. 与 RPG-Recon 的重叠

- 关注对象高度接近：告警级联 + 因果关系图 + 源节点识别。
- **评价口径直接命中我方**：使用 **Node F1、Case EM、Graph F1、nSHD** 评价——
  说明「对图结构本身打分」在这一社区已有被接受的做法与指标命名。我方图评价协议
  需要正面对照这些口径。
- 同样显式处理**无环性约束**（确定性代码校验 acyclicity），与我方 DAG 组装同构。

## 6. 关键不同条件

- **粒度**：节点是告警类型/事件，不是物理设备；我方节点是设备，且边必须落在原始
  `task_topo` 邻接上。EvoCause 未报告是否约束边必须对应物理连接。
- **监督条件**：EvoCause 需要带标签的对齐集来选图；我方 P0 局部支持不使用图标签训练。
- **起点假设**：EvoCause 一次性预测所有入度为零的告警 ⇒ 隐含**允许多个根同时成立**；
  我方限定**单设备根**，Top-K 是相互竞争的单根假设。这是任务定义的实质差异。
- **LLM 使用**：EvoCause 在改进阶段用 LLM；我方实验不得调用外部 LLM API。

## 7. 可能的审稿质疑（对我方）

1. 「EvoCause 已经用 Graph F1 / nSHD 评价告警因果图，你的图指标有何不同？」
   ——需明确：节点粒度（设备 vs 告警类型）、边域（物理邻接 vs 任意告警关系）、
   单根 vs 多源，以及我方对 unknown 掩码与部分标注的处理。
2. 「用 LLM 引导图编辑 + 确定性校验的闭环，与你的『局部支持 + 结构组装』分离，
   是否只是工程取舍？」——需说明我方不使用外部 LLM 的约束来源，以及局部支持
   不用图标签训练这一点。
3. EvoCause 附带的 **TeleRCA benchmark（485,681 告警事件、5,621 资源、专家标注）**
   可能成为审稿人要求我方对照的公开数据。需评估其可用性与场景差距。
