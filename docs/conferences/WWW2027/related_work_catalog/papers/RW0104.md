## 1. 论文解决的问题

电信/云/微服务系统故障时产生**关联告警级联**。RCA 要找出每次级联的**起始告警**。
常见做法：从观测日志学一个因果图，再预测每个 incident 子图中**入度为零**的告警。
问题：学到的图是固定的，无法利用历史事故的专家诊断来改进。EvoCause 用 LLM 提议图编辑、
确定性代码校验，在带标签对齐集上选图，把这一闭环补上。

## 2. 节点与图的定义（**§3.1，本卡最关键的更正**）

原文 §3.1 逐字定义：

> "We represent the triggering relations among the **alarm types** **A** with a directed
> acyclic graph **G** = (**A**, **E**), which we call an **alarm propagation graph (APG)**.
> Its **nodes are alarm types**…"

且同节说明：同一告警类型的重复出现**只计入一次**，并**假设告警类型之间的触发关系在整个
观测窗口内保持不变**。

因此：
- **节点 = 告警类型（type-level），不是设备，也不是单次告警实例。**
- 边 = 告警类型之间的触发关系（要求无环）。
- 事故中的作用范围是**诱导子图**（incident-induced subgraph）。

**这与本文的设备级、incident-specific 传播 DAG 在粒度与对象上都不是同一件事。**

## 3. 评价对象与指标（**§4.1、§4、式 (19)**）

原文在贡献段明确区分了两类评价：

> "we evaluate both RCA (**Node F1 and Case EM**) and **graph reconstruction
> (Graph F1 and nSHD) on ten synthetic DAGs**, together with RCA performance on TeleRCA"

- **Node F1 / Case EM**：评价**根告警集合**（RCA），在 **TeleRCA 真实数据**上报告。
- **Graph F1 / nSHD**：评价**图结构重建**，**只在 10 个合成 DAG 上**报告。

**式 (19)**：

```
Graph F1 = 2|Ê ∩ E| / (|Ê| + |E|)          （有向边 F1）
nSHD     = SHD(Ĝ, G) / |E|                  （分母 = 真值边数）
SHD(Ĝ,G) = N_add + N_del + N_rev            （增 + 删 + 反向）
```

**nSHD 的分母是真值边数 |E|**，不是预测边数、不是并集——引用时必须写明。

## 4. TeleRCA **没有传播图真值**（**§2.3、§4.1**）

原文 §2.3 逐字：

> "It does not provide a **ground-truth propagation graph**, so we use it to evaluate
> RCA rather than exact graph reconstruction."

TeleRCA 规模：485,681 个告警事件、194 种告警类型、5,621 个资源、生产电信网专家标注。

**因此：不能把 EvoCause 的真实数据结果与「设备级事故传播图」比较，
也不能把它的 Graph F1 / nSHD 当作真实数据上的图恢复成绩。**

## 5. 撤回原卡的「社区已接受指标口径」推论

原卡据「EvoCause 用 Node F1 / Case EM / Graph F1 / nSHD」推断
「对告警因果图打分在该社区已有被接受的指标口径」。

**该推论撤回**，因为：
- 这些图指标**只在合成数据上报告**，真实数据只评根集合；
- 它来自**单篇预印本**，不能代表社区口径；
- 指标虽与本文建议的边级 F1 同名，但**节点粒度（告警类型 vs 设备）、
  真值来源（合成 DAG vs 事故标注）、分母定义**都不同。

**可保留的准确表述**：EvoCause 是重要的 L1 近邻，它在**合成数据**上用
**有向边 F1 与 nSHD** 评价图重建——这提供了一个**同类任务的指标命名先例**，
但**不构成真实数据图评价的社区惯例证据**。

## 6. 撤回「与本文 P0 同构」的推论

EvoCause 用确定性代码校验**无环性**，本文 P0 也输出 DAG。原卡据此暗示两者「同构」。

**撤回**：共同使用无环约束是**很弱**的相似性。真正的差别在于：
- 本文 P0 的边**必须落在原始 `task_topo` 邻接**上，且施加**根距离严格递增**约束；
- EvoCause 的边域是告警类型之间的任意触发关系，**未见物理邻接约束**；
- 本文的起点是**不确定的 Top-K 竞争单根**；EvoCause 一次性预测**所有入度为零**的告警。

## 7. 与 RPG-Recon 的重叠（保留的部分）

- 同样面对「告警级联」与「起始告警识别」。
- 同样把**图结构**作为显式输出对象之一。
- 人工标注的根告警集合（专家诊断）是其监督来源，与本文依赖工程师标注的处境类似。

## 8. 关键不同条件

| 维度 | EvoCause | 本文 |
|---|---|---|
| 节点粒度 | 告警类型 | 物理设备 |
| 边域 | 告警类型间触发关系 | 原始拓扑邻接 |
| 根假设 | 预测全部零入度告警（可多源） | 单设备根，Top-K 竞争假设 |
| 图指标数据 | **仅合成 DAG** | 真实事故标注 |
| 监督 | 需带标签对齐集选图 | P0 局部支持不用图标签训练 |
| LLM | 改进阶段用 LLM | 实验不得调用外部 LLM API |
