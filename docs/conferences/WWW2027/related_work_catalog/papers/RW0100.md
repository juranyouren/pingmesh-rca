# RW0100 — ErrorPrism: Reconstructing Error Propagation Paths in Cloud Service Systems

2026-09-15，T009 定点修订。Pu 等；ASE 2025，3534–3545。

旧卡快照存于 graph_metrics_literature/RW0100.before_T009.md。

## 问题、输入、方法、输出

从末端错误日志恢复源头到日志位置的函数传播路径。输入包含源码和日志，
静态分析构建函数调用候选，LLM 迭代回溯。节点是函数，不能继续写“错误模板/组件粒度未知”。
§III-B/D 描述方法；搜索可探索分支，评价单路径不等于完全不能探索分支。

## 数据与评价

- §IV-A1：102 个错误事件/模板对应的人工核验路径；复盘记录与开发团队源码回溯构造参考。
- §IV-A3 Eq.(2)：路径完全匹配的 Accuracy；分母为错误模板数量。
- Eq.(3)：静态候选的 Precision 是每模板“参考路径函数数/候选唯一函数数”再平均。
  不是有向边 precision，不能与路径 Accuracy 直接看作同一指标提升。
- Table I 按 hop=0/1/2/3/≥4 及 Total 列展示；**不是 Accuracy/Inference Time 两列**。
- Fig.5 为平均计算推理时间；不是工程师诊断或修复时间。
- Fig.4（复用 T007 R6 核验）0/1/2 hop 为 8/31/42：0–1 hop 38.2%，0–2 hop 79.4%。
  hop 定义为错误上下文包装次数，不能机械当作设备跳数。

## 限制与本文责任

§IV-E 讨论仓库范围过宽带来开销、过窄漏关键代码；§IV-B 也指出模板解析可能混合不同路径。
因此源码条件、模板到路径对应和设备映射需单独验证；不能因为输入不同就称本文更强。
单路径也是图，换成设备 DAG 不是自动贡献。本文须证明独立关系正确性与分支/使用者价值。
是否盲标、标注者是否见过方法输出，以及正式版与作者稿分页一致性均未核准。
