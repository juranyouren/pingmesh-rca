## 2. 重点会刊年份覆盖

### 2.1 方法与其局限（**必读**）

本轮用 Crossref `query.container-title` 对 17 个重点会刊做 2015–2026 逐年探测，
结果存于 [catalog.xlsx](catalog.xlsx) 的 `Coverage` 工作表。

> **该方法有明确局限，不能被当作「该会刊每年出版了多少篇」。**
> `query.container-title` 是**相关性排序参数而非精确过滤**，返回的是全库重排结果的上限 1000 条，
> 再按 container 名称本地过滤。因此表中的 `n_records` 只是**粗粒度检索记录**，
> 不是出版量普查。**本目录不基于该表做任何「覆盖率百分比」声明。**

OpenAlex 的 source 作用域统计（可给出真实逐年出版量）**本轮未完成**——
当日配额耗尽（`Resets at midnight UTC`），已记入 [search_log.md](search_log.md) §6。

   2026 年 L1 候选（PropLLM、EvoCause、NetCause、Fault-Propagation-Aware Benchmark 等）

   **最后一轮（R5）无新增 L1 核心近邻**，新增条目均为背景或方法基础。

   但不替代其他覆盖检查**。本轮实际做到的是**一轮**无新增（R5），
   R4 仍有方法基础层新增。因此本轮停止是**基于可访问范围的收敛判断**，
   **不是**「已证明穷尽」。

## 6. 本轮最重要的事实性发现

1. **最强的直接近邻是两篇 2026 年预印本，而不是数据库里的老论文**：
   - **PropLLM**（arXiv:2606.00582）：逐跳回溯传播路径 + 拓扑因果先验，
     与本文问题设定高度重合；输出是**链**不是图。
   - **EvoCause**（arXiv:2607.27290）：LLM 引导演化因果图，用 **Node F1 / Case EM /
     Graph F1 / nSHD** 评价，并发布 **TeleRCA** 专家标注 benchmark（485,681 告警事件）。
     **说明「对告警因果图打分」在该社区已有被接受的指标口径，本文必须正面处理。**
2. **仓库旧材料的三个简称不是正式题名**：COLA、REASON、CORAL 均为系统名，
   其中 REASON 与 CORAL 的正式题名与旧记录完全不同（见 §5.3）。
   COLA 与另存条目实为同一篇，已合并。
3. **「网络侧没有传播关系评价」这一旧概括必须撤回**：NetEventCause 已有事件级局部
   原因关系的 ACC@k 与参考关系对照；APGNN 的题名本身就是「告警传播图」。
   正确表述是「未查到与本项目同粒度、同输出对象的完整设备 DAG 指标先例」。
4. **跨领域已有可对照的图评价实践**：WWW 同级的 CausIL 报 Adj/AH/SHD；
   FSE 的 ProAlert 用传播路径做告警摘要；ASE 的 ErrorPrism 以路径 exact-match 评价。
   本文的图指标设计应引用这些**同类输出**的工作，而非只引用因果发现工具。
5. **一个对我方评测设计有利的独立经验依据**：*Complexity at Scale*（arXiv:2504.13141）
   用阿里巴巴生产追踪数据证明**调用图高度时变、依赖长尾**，
   直接挑战故障管理研究中「依赖图固定」的常见假设——支持我方不把长期依赖图当事故真值。
