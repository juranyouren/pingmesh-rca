更新日期：2026-09-16。最新方案入口：[最新方案与文档同步说明](./2026-09-16_最新方案与文档同步说明.md)。

## 总体主线

本文提出 **RPG-Recon（Root-conditioned Propagation Graph Reconstruction）**，用于从 Pingmesh 异常触发后的不完整设备观测中恢复与当前 incident 对应的设备级传播解释 DAG。Web 服务依赖 DCN 通信；Pingmesh 提供异常入口，但后续仍需判断设备异常之间的关系，以及哪些检查和恢复动作有必要。

论文不把传播图说成真实 ECMP 路径、完整结构因果模型或自动修复系统。输出是受观测支持、受原始 `task_topo` 邻接约束的设备级有向影响假设，并附证据引用、替代解释和未知关系。单设备根范围不变；Top-K 是相互竞争的单根锚点，不表示多根同时故障。

## 1. 引入

从 PPT《pingmesh治理》的 A/B/C/D 示意开场：A→B→{C,D}，排名为 A,C,D,B；A 已排第一，因此图的潜在价值在恢复/检查动作组织，而不是根排名改善。图示的“4 devices inspected → 2 devices handled”只作示意计数，不能写成 50% 效率或 MTTR 收益。B 是否在 A 修复后仍必须处理、C/D 的 `Established` 状态是否异常、反馈延迟与停止条件均需独立证据。

再用旧的合成 `DEMO_001` 说明观测与操作的区别：端点异常、C/S 事件、物理拓扑和缺失记录可以支持关系核查，但不能由时间、状态或无记录直接推出传播方向。案例设计中分开绘制观测、人工操作、候选关系和最终解释图；PPT 案例与 DEMO_001 不混用。

## 2. 以往工作

按四组压缩相关工作，并避免“前人只有排名/没有图”的概括：

1. **测量与路径约束定位**：Pingmesh、deTector、NetBouncer、TraceRCA 通过端点/路径/trace 观测缩小故障范围，但这些路径或调用 trace 不是本文仅有的设备告警和原始拓扑自动提供的输入。
2. **告警聚合与事故范围分析**：COLA、SkyNet 利用时空统计、拓扑、SOP 或层次告警组织支持定位；聚合、范围或连接图不必然等于当前事故的设备级有向影响关系。
3. **事件依赖与传播建模**：NetEventCause 已恢复告警实例级传播 DAG，NetCause 使用异构事故拓扑支持根因分析，Hawkeye 在专门的 PFC/端口遥测下构造溯源结构。需要比较事件、设备和流/端口粒度，以及观测条件和评价对象。
4. **知识与 LLM 辅助诊断**：RCACopilot、BiAn 组织诊断信息、根因类别、设备排名和解释；排名、信息采集或自然语言推理不能直接替代按设备边评分的传播图。

本文的剩余问题不是简单地“加入拓扑和时间”，而是在上述不完整设备观测下，如何连接竞争锚点、局部关系歧义和事故级一致结构。

## 3. 两个具体挑战

### C1 — Local Ambiguity / 局部关系歧义

对相邻设备 (u,v)，需同时判断直接关系是否存在及方向。时间先后、严重度、拓扑位置和接口/peer 语义只提供旁证；共同原因和观测缺失仍可能导致竞争解释。缺失支持必须保持未知，不得自动作为 No Direct。

### C2 — Global Consistency / 全局一致性

局部支持独立组合后可能成环、脱离候选锚点、彼此冲突或留下未解释分支。图合法不等于关系正确；需要在共同锚点条件下选择和组合关系，并保留替代解释与证据缺口。

旧的起点不确定性作为 M3 的锚点估计误差处理，不再列为第三挑战；其影响用固定预测根、Direct Oracle、Top-1/Top-K 和 root correction/corruption 进行对照。

## 4. 三个模块与方法组织

- **M1 — Incident Evidence Graph Construction / 事故证据图构建**：汇总 Pingmesh 上下文、告警、日志、时间戳、拓扑和证据引用，形成事故级共同证据基础；不宣称已有同名独立实现。
- **M2 — Local Propagation Relation Modeling / 局部传播关系建模**：在原始相邻设备对上表示正向、反向、No Direct、unknown 和冲突支持。
- **M3 — Anchor-Guided Global Propagation Reconstruction / 锚点引导全局传播图重建**：估计/接收候选锚点，在锚点条件下进行构图和一致性选择，输出传播解释 DAG。

现有两阶段代码映射为：Stage 1 PC-STGR 提供 M3 所需的锚点候选排序；Stage 2 P0 涵盖 M2 的局部支持与 M3 的条件 DAG 组装。概念改名不代表代码已重构。当前 P0 的最短拓扑距离严格递增是强建模限制，不是真实传播规律或全局最优保证。

## 5. 贡献与验证

1. 组织事故证据、竞争锚点和条件传播解释，使根不确定性可以传递到图恢复；不把 RCA 或 Top-K 单独称为新颖性。
2. 分离局部关系支持与锚点引导的整体组装，显式保留方向竞争、未知和替代解释；该主张须由 C1/C2 对照实验支持。
3. 将图质量与决策价值分开评价：按冻结协议报告有向边 P/R/F1、节点/完整图指标和结构合法性，并区分 raw 与等价投影、固定根与端到端设置；动作价值需要相同反馈/停止规则下的真实或明确受控记录。

### 可证伪假设

- H1：保留竞争关系优于提前硬选方向；无收益则弱化该主张。
- H2：完整一致组装改善图质量，而非只减少环或边数。
- H3：在相同初始排名、观测、反馈和权限下，图辅助策略减少冗余动作；无真实动作记录不声称 MTTR 收益。
- H4：锚点错误会影响图恢复；用 Shared、Direct Oracle 和完整流程分离根误差与图误差。

## 图片统一规范与 prompt 要点
