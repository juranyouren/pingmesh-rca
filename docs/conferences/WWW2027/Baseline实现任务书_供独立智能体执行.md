## 3. A0：公共数据契约与评测

### 3.1 输入、标签分开交付

建议采用一案例一个 `IncidentInput`，原始设备 ID 作为案例内标识，跨案例 ID 是否稳定另行审计。未知设备类型/事件类型显式编码为 `UNK`，禁止把不同案例的“第 0 台设备”当成同一个变量。

```python
IncidentInput = {
    "case_id": str,
    "group_id": str,
    "window": {"start": str, "end": str, "cutoff": str, "timezone": str},
    "devices": [{"id": str, "type": str | None}],
    "physical_links": [{"u": str, "v": str, "evidence_ids": list[str]}],
    "endpoint_context": dict,
    "events": [{
        "event_id": str, "device_id": str, "event_type": str,
        "event_time": str | None, "record_time": str | None,
        "severity": str | None, "message": str | None,
        "source": str, "observed_fields": list[str]
    }],
    "observation_coverage": dict | None
}

# 仅训练入口接收当前训练折的监督；评测器单独读取测试真值。
IncidentLabels = {
    "case_id": str, "root_device": str | None,
    "root_status": str,
    "positive_nodes": list[str], "positive_edges": list[tuple[str, str]],
    "known_node_mask": list[str], "known_edge_mask": list[tuple[str, str]],
    "graph_complete": bool, "label_version": str, "label_provenance": dict
}
```

此处是字段形状示意，实际序列化使用 JSON Schema 定义，Python 示例中的类型名不是可直接发送给算法的 JSON 数据。

必须交付 `raw_to_input_mapping.md`：逐项说明真实文件、字段、时间格式、单位和缺失行为。保留真实触发时间、事件时间和采集时间的区别。窗口必须从预测时可得的触发信息及固定规则确定，不能用标注传播边的时间范围来截取。无法确认完整采集时，不把“窗口内无记录”解释为“设备正常”。

所有 baseline 读取统一候选设备全集；算法内部筛选允许，但必须记录被删设备及召回损失。不能沿用 BiAn 默认六台设备截断，也不能只给外部方法有事件设备、同时允许本文方法选择静默设备。计算资源要求裁剪时，先定义与模型分数和标签无关的公共候选规则，并单独报告覆盖范围。

### 3.2 建议接口和输出

```python
fit(train_cases, train_labels=None, validation_cases=None, validation_labels=None)
predict_root(incident) -> RootPrediction
predict_raw_graph(incident) -> NativeGraphPrediction
adapt_graph(native_output, incident, root_condition) -> DeviceGraphPrediction
```

不是每种方法都要实现所有接口；不支持的能力用方法元数据声明。Oracle 根仅由包装层作为 `root_condition` 传入，不能读取其他测试标签。本文原生根条件方法可以在原生推断中用根；外部非根条件方法保持原生图不变，仅在统一适配阶段用根。

预测文件至少包含 `case_id/method/version/fold/seed/status/root_ranking/native_graph/device_graph/graph_condition/adapter_version/timing/diagnostics`。根分数、边分数必须注明语义；注意力、系数、显著性和归因值都不能未经校准写成概率。每条适配边应能追溯到原模型边或原观测，支持记录可以是时间片及变量，不要求所有方法都有日志文本解释。

区分 `unsupported_task`、`input_ineligible`、`runtime_failure`、`abstained` 和 `ok`。其中空图可以是成功输出的根单点图，也可以是失败；不能凭边数判断状态。

### 3.3 分组、训练与逐例推断

1. 冻结案例清单、标签版本、事故组、训练/验证/测试划分和随机种子。先查重复导出、重叠窗口、同源事故及合成衍生关系，再分组；不把目录名不同当成事故独立。小样本可用 grouped 外层交叉验证，内层训练/验证选择超参数；折数由独立事故组数量决定。
2. NetEventCause 及其他跨案例学习模型仅从训练事故拟合共享参数、词表、标准化统计及知识库；监督只限训练标签。验证标签可用于预先声明的超参数选择，测试标签只进入评测器。
3. PCMCI+、DYNOTEARS、TCDF 可预先声明为 **逐 incident 无标签图发现**：对当前允许窗口进行统计估计或优化，是推断过程的一部分；每例重置，不汇集未来或其他测试事故。其耗时全部计入单例诊断成本。该设置不等同于跨案例训练后测试，必须在表中披露。
4. 如果改用历史训练图，必须定义它如何随当前事故产生特定输出。不能把一个固定的历史全局图复制到每例后称作已经恢复了不同故障的实际传播。
5. CORAL 等在线方法使用独立的时间顺序协议：当前事故只能访问当时可得的历史和当前前缀。随机 grouped folds 不能直接冒充在线评测；每个实验流的状态初始化、更新和重置都要记录。
6. 同一套实验固定可观察的截止时间。离线完整故障窗口与实时早期诊断分开，不能拿使用故障结束后信息的方法声称实时效果。

### 3.4 通用设备图适配器

主设置采用确定性的 `device_greedy_v1`，由 A0 实现一次。名称明确附加 `+ device adapter`，保存三层产物：原生图、未经结构筛选的设备投影、最终根条件图。

1. 原生节点按输入归属映射设备；同设备关系保留原生诊断但不输出设备自环。时间图的滞后方向保持“过去的原因设备 → 当前的结果设备”。
2. 仅聚合原方法已经支持的有向关系；同设备对多条支持默认取最大值，保留全部来源列表。未定向关系另存，不按设备 ID、根距离或真值强制定向。若只有二值支持，所有边同权并披露 tie-break。
3. 先保存原始投影，记录非物理邻接、双向、环、孤立节点。然后按原始物理邻接过滤，不补最短路径，不引入 P0 支持分数。
4. 给定根 r，去除指向 r 的候选边；按支持降序、稳定的设备 ID 顺序尝试加边，只有不成环才保留；最后保留 r 及其有向可达部分。允许汇聚和多个父节点，不额外强制为树，也不施加 P0 的根距离严格递增限制。
5. 每个删边决定输出原因，分步报告删边比例与有效性。不同方法分数只用于各自内部排序，不在方法间比较数值大小。
6. Oracle 与共同预测根只改变适配步骤，不能重算根无关的原生边。若以后增加更强的通用适配，应预先冻结并让所有外部图方法共同使用，旧适配保留为敏感性实验。

适配器只使输出满足本文比较契约，不能证明边是真实因果关系。使用相同适配器也不自动消除本文解码器与外部方法之间的结构先验差异，须通过本地边法加同一适配器的消融量化。

### 3.5 表格与指标

建议拆成 Root、Oracle-Graph 和 End-to-End 三张表；另有“共同 PC-STGR OOF 预测根”的图实验，用于固定相同错误根比较传播模块，不混称外部方法的自主 Full-Graph。

- Root：Top-1/3/5、MRR、候选覆盖、失败率。名单中未返回真根则未命中。只返回部分排序时不靠追加真根补齐。
- 图：有向边宏平均 P/R/F1、节点宏平均 P/R/F1、图规模、物理合法率、无环率、根可达率。完整标注事故才计严格整图匹配；部分标注只在已知范围计分，未标注关系不作负例。
- 节点分数建议同时给出包含根和排除已知根的结果，避免 Oracle 根单点抬高传播节点表现。边的空真值/空预测计分约定预先冻结，并单独给出零边事故数量。
- Full-Graph 必须报告根准确率与普通 Edge-F1，同时补充 `Joint-Edge-F1 = mean(1[pred_root == true_root] * EdgeF1)`；普通 Edge-F1 可以在根错时仍较高，不能独自代表根和图都正确。
- 完整标签上的联合整图正确要求根、节点集、边集全部匹配。结构等价投影只作为另列指标，不覆盖原设备粒度指标。
- 置信区间按独立事故组进行配对重采样；不把同事故的设备或边当独立样本。学习方法固定多随机种子，报告均值及波动；置信区间和种子差异各自说明。
- 运行失败保留在冻结分母中，主要任务分数按失败处理，并另报成功例质量。输入门槛须在查看测试效果前确定；若只适合部分事故，单列子集及覆盖率，不把每种方法不同子集的均值直接排在一起。
- `X` 仅指任务能力不适用；“尚未实现”“输入不满足”“运行失败”用不同状态表达。候选审计表与最终结果表分开。

A0 验收：打乱或替换测试根/边标签后，普通 Root/Full 推断产物应完全相同；Oracle 只允许指定根相关部分变化。准备包含双向边、设备折叠环、未知边、根不在排序、空输出和部分标注的最小案例，核对适配与计分。检查没有因错误/失败而少输出 case_id。

## 4. A4：时间序列可行性与统一分箱

从真实事件时间生成 `X[time_bin, device]`，第一版采用观测到的告警/日志事件计数，告警与日志来源另存。不同事件类型通道是可选扩展，不能每个方法自行混用不同通道。原始计数是首选，连续方法可用明确命名的 `log1p(count)` 变换；二元“本箱是否有事件”另作离散版本，不能声称这些序列就是原有连续 KPI。

起点、终点、Δ 和最大滞后共同冻结。Δ 可在训练侧从 5/10/30/60 秒等小范围中选，但候选值必须结合实际时间精度和窗口长度审计后确定。这是工程搜索建议，不是文献推荐值。允许观测的无事件箱记 0，采集未知箱用 mask；没有覆盖信息时只可称“日志计数为零”，不能据此生成正常状态标签。

每例输出设备数、窗口长度、唯一时间戳数、分箱数、非空箱比例、每变量方差、有效样本数、缺失率、可用最大滞后及设计矩阵条件。常量变量可以从拟合器中剔除，但必须保留在公共候选域中并记录“不可估计”，不能把真值也删掉。

禁止跨事故直接拼接序列造成虚假前后关系；独立多序列训练只有在变量身份和机制假设成立且实现尊重边界时才可用。不得插值出伪造告警、随机扰动时间来造传播顺序，或靠无限增加空箱制造样本量。

在训练/开发事故上评估短窗口和稀疏性是否使方法退化；没有统一适用的“箱数大于设备数就足够”规则。若观察条件不足，交付不适用原因和覆盖表，并把这类方法作为条件性迁移实验。通过 A4 不代表数据已经满足平稳性、无隐变量或可识别性，只说明可以实施和解释该实验。

## 5. A1：NetEventCause 论文机制复现与设备适配

这是最优先、也最需要人工复核的实现任务。建议完成后命名 `NetEventCause-ODE-reimpl-Device + device adapter`；若只跑公开 ERPP 替代模型，必须另外命名，不能在结果表里仍简称完整 NetEventCause。

### 5.1 已确认的起点与障碍

- 原论文文本：[本地全文](../../papers/NetEventCause_%20Event-Driven%20Root%20Cause%20Analysis%20for%20Large%20Network%20System%20Without%20Topology.txt)。原文 §IV-A–D、Algorithm 1/2 是复现依据。
- 作者代码已在 [本地目录](../../../Baseline/NetEventCause/NetEventCause-main/README.md)；[公开 README](https://github.com/yuanzhaolin/NetEventCause) 明示部分源代码被替换。
- `scripts/toy_all.sh` 默认选择 ERPP。`cause/event/tasks/train.py`、`detect/attribution_rca.py` 引用 `models/ode_rnn.py` 和 `models/spnpp.py`，但本次核查的对应 models 目录缺少这两文件。
- `detect/attribution_rca.py` 的 `cause_score_modify` 按类型编号 0–4 写死部分关系，而且会先将支持抬到至少 0.01；该行为也存在于 [公开归因代码](https://raw.githubusercontent.com/yuanzhaolin/NetEventCause/main/detect/attribution_rca.py)。不能用于本数据的正式实验。
- 仓库另有 `Baseline/NetEventCause/NECAnalyzer.py`，是指数核 Hawkes 根排序器，不是上述论文模型；其事件抽取读取 `time/confirm_time`，尚需与当前主要 `alarm_time` 字段对齐。

因此，A1 第一项交付必须是 `reproduction_gap.md` 和锁定的代码版本/文件哈希，不是直接运行 toy 然后给出“已复现”。缺失核心模块可依论文重建，已有辅助代码仅在语义核对后复用。

### 5.2 实施步骤

1. **事件编码。** 从 A0 的事件输入构造 `(relative_time, event_type, event_id, device_id)`；事件类型按论文的告警类型与实体类型组合，设备归属单独保存。每个事故独立设时间原点和观测区间，不把不同事故拼成连续过程。相同时间戳的事件不通过随机抖动创造因果顺序；若实现要求严格序列顺序，冻结 tie-break、记录同时事件比例，并单独检查这部分边的敏感性。
2. **连续时间模型。** 按 §IV-A 恢复 ODE-RNN、事件类型嵌入、强度解码及似然积分，保留 §IV-D 的空历史正则。不能只恢复一个 GRU，或只训练 NLL 却漏掉维持先验一致性的项。先在小型合成事件过程检查积分、梯度、训练稳定性，再接真实训练折。
3. **根告警先验。** 原文 §IV-B 的先验强度估计需要少量根告警标注；设备根标签不等于该设备上所有告警均为根告警。优先使用训练折内已有、可核验的事件级根标注。如没有，第一版可定义工程先验 `mu_k = rho * count_k / total_observed_duration`，在训练侧内层验证中只调整共享 rho 和预声明阈值，并命名 `prior-calibrated adapt`；这是本项目的弱监督校准方案，不能称原文先验估计。须报告其与额外事件标注版的监督差异。不可用测试事件或测试根标签估计比例。
4. **归因。** 按 §IV-C 实现对历史事件的 IG；空历史基线保留时间并将历史事件嵌入置零。根判定与衍生事件的 Top-K 原因选择遵循 Algorithm 2。核对 IG 数值积分精度、历史方向、K、阈值及负贡献处理。原文根阈值默认 0.2，与公开检测代码中的 0.5 不一致，必须在配置中注明采用依据。
5. **原生输出。** 为每个事件保留强度、根评分、根/衍生判定、原因事件列表、归因支持及异常数值标记。公开代码的未知类型直接设根概率为 1 不宜照搬；采用训练词表的 UNK 或明确不可判定策略并披露。若先验/模型失配导致根评分超出概率范围，记录异常，不能静默截断后声称已校准概率。
6. **设备排序。** 首版 `device_score(d) = max(root_score(e) for e on d)`；这是输出聚合约定。无事件设备保留在候选全集中，标记原生不可评分，确定性排在已评分设备之后；不借用 P0、告警投票或其他模型替其评分。全案例无有效事件时记录失败/弃权，不伪造有效排名。
7. **设备图。** 原生事件关系按事件所属设备映射，使用 A0 的共同适配器。Oracle 用真根、自主 Full 用本方法 Top-1；另外可跑共同 PC-STGR OOF 根，但须单列。
8. **保存运行证据。** 记录模型实现来源、作者代码修订、先验来源、监督粒度、K、ODE 求解配置、IG 步数、训练预算及每例时间。设备适配不会消除原方法依赖准确事件时间等假设，需披露时间并列、缺失、延迟的覆盖情况。

验收必须包括：训练似然含正确的区间积分；模型在未观测的将来事件到来前不访问它；空历史正则和 IG 基线实现相符；人工 toy 因果规则不出现在正式归因调用链；参数和先验不跨折；A→B→A 的不同事件序列可在事件层合法、设备折叠后检测出环；替换测试标签不影响根排名与原生事件图。若最终未补齐 ODE/正则/归因，交付部分实现状态，不报告为原版 NEC。

## 6. A2：BiAn-adapt（本地模型）

来源：[作者论文](https://ennanzhai.github.io/pub/sigcomm25-bian.pdf) §4.1–4.3、Appendix A；现有 [BiAn Pipeline1](../../../Baseline/BiAn/bian_pipe1.py) 可复用本地调用和结果解析，但不等于完整方法。

第一版建议命名 `BiAn-three-pipeline-adapt, local model, without historical knowledge evolution`，在表格可缩写为 `BiAn-adapt`，脚注完整披露。

1. 将原论文各监控来源和异常分析场景与 A0 字段逐项对应。现有告警/日志可支持的设备异常分析、来源摘要、跨设备解释应保留；缺少命令历史、专有 SOP、流量指标等就注明缺项，不从故障答案反向编造诊断规则。
2. Pipeline 1 对公共候选设备全集生成设备摘要及初始排序。必要时分批处理，保留统一证据预算规则；不能先按告警量取六台再称全设备定位。
3. Pipeline 2 按论文的嫌疑设备拓扑摘要机制构造输入，只用真实物理图。论文内部最短路径用于拓扑摘要时可以保留，但这些路径不能宣称是实测探测路径或预测传播图；它与公共设备图适配器“禁止补边”的用途不同。
4. Pipeline 3 汇总带事件 ID 的全局时间线，保留事件/记录时间区别、同时事件及未知时间。不得因为某设备最终是真根才提升其时间线权重。
5. 按原文将三条流程结果交给联合推理模块。原方法的 Top-p 内部筛选可保留，参数在训练侧固定，报告保留比例和候选损失；为公平覆盖，返回前保留初始阶段对全部候选的排序及最终更新规则。
6. 保留重复联合推理后按名次聚合的思路。首版可以采用论文的三次 Rank of Ranks；记录每次排名、平均名次、平分处理和总 token。单次版本可以作预算消融，不能混用最好的一次结果。
7. 历史知识演化首先作为可选模块；缺少训练期历史材料时主版明确关闭。有材料时仅使用训练折 incident 的分析和反馈，知识摘要、提示版本及检索来源逐折保存。测试答案不得参与 reflection。
8. 只连接真实本地模型后端，固定模型、温度、token 预算、超时和重试规则；不启用 mock。JSON 失败允许预定义格式修复/重试，仍失败则记录错误，不能静默回退到启发式并算作 BiAn 成绩。保存可核查的证据摘要及模型输出，不要求生成或保留隐式内部思维过程。

输出：Root 排名、各阶段候选数、可用/缺失输入表、证据引用、模型与提示版本、token/时延、失败原因。Oracle/Full 图能力不支持。验收包括：无测试标签进入提示；所有证据 ID 存在；设备全集不因六台截断丢失；三条流程都实际执行；名次聚合可重算；不能因模型失败排除事故。

## 7. A3：SkyNet-inspired Alert Voting

来源：[SkyNet 作者论文](https://ennanzhai.github.io/pub/sigcomm25-skynet.pdf) §7.1。论文描述设备/链路告警对自身及相连链路或设备投票，但未给出足以直接照搬的所有字段归属和数值规则；单位票及本项目设备化是适配选择。

第一版选定 **告警归属驱动的设备投票**，输出仍只用于 Root：

```text
V(e) = 由原始告警归属及明确设备/链路连接可以确认的候选设备集合
score(d) = sum_e 1[d in V(e)]
```

对设备自身告警，至少投所属设备；只有告警字段明确涉及对端/接口，或预先冻结的设备化规则明确定义邻接扩展时，才增加相邻设备。对明确链路告警，映射两个真实端点。一个去重事件对同一设备最多一票；缺失映射不猜测。若为了与旧文稿一致采用“设备及全部一跳邻居”扩展，必须另命名 `SkyNet-inspired one-hop voting`，它是本项目扩展，不能说是论文给出的完整算法。

A3 必须先交一张 `alarm_type → V(e) rule → required field → missing behavior` 表再运行。首版事件权重均为 1；不按最终准确率调整类型/严重度权重。重复记录根据输入事件 ID 或固定字段签名去重，不把短时间内真实重复故障事件随意合并。拓扑多重边不能增加同一票的权重。

原生输入以告警为主；日志仅在公共预处理已将其明确归类为告警时使用。直接把全部日志也当等价票需要另列 `alerts+logs adapt`。保留全设备排名、逐票来源、投票设备集合、被忽略告警及平分情况；首版平分使用固定设备 ID，另报平分率，不用真根打破平分。

验收：手算一个三设备两链路案例验证每张票；重复告警不会重复投票，真实不同事件仍各计一票；未知接口不扩大邻域；根标签变化不影响分数；无票设备仍在候选列表。没有任何传播图输出，不与 P0 连接后回填自身 Full 列。

## 8. A5：PCMCI+-Graph + device adapter

来源：[原论文](https://proceedings.mlr.press/v124/runge20a.html)、[Tigramite](https://github.com/jakobrunge/tigramite)、[接口文档](https://jakobrunge.github.io/tigramite/_modules/tigramite/pcmci.html)。原输出是时间序列 CPDAG，可能含未定向同期边；它不是保证完全定向的设备 DAG。

实施步骤：

1. 锁定 Tigramite 版本，跑通作者小示例；连接 A4 输出的单例序列和 mask。设备顺序映射必须显式存储。
2. 连续计数变换可使用 `ParCorr` 作为线性近似并在名称/配置中披露；离散二元版本使用适合离散数据的 CI 检验。不能把高斯线性检验直接描述成对稀疏计数分布成立的保证。
3. 调用 `PCMCI(...).run_pcmciplus(tau_min=0, tau_max=..., pc_alpha=...)`。固定检验、最大条件集、显著性/FDR设置与调参预算。不要用普通 `run_pcmci` 替代 `run_pcmciplus`。
4. 保存 `graph/p_matrix/val_matrix` 和滞后。根据官方箭头约定解析方向；不要仅按 p 值阈值化再忽略原生方向判断。保留同期未定向、冲突关系，不强制选一个 DAG 成员冒充识别结果。
5. 有向关系映射设备后交给公共适配器。候选支持排序使用预先固定的检验统计量方案，注明不是概率；显著性负责关系选择，不能把 `1-p` 解释成传播概率。
6. Root/自主 Full 均不提供。Oracle 与共同预测根来自包装层；额外报告未定向覆盖、骨架质量，避免只看定向 F1 隐藏等价类歧义。

验收：已知滞后方向的合成数据验证索引；保留自回归关系的原生记录但无设备自环；未定向边不能在设备图中变为双向确定边；替换 Oracle 根不改变原生时间图。

## 9. A6：DYNOTEARS-Graph + device adapter

来源：[原论文](https://arxiv.org/html/2002.00498v2)、[作者团队 CausalNex 实现](https://github.com/mckinsey/causalnex/blob/develop/causalnex/structure/dynotears.py)。优先复用实现，不能因为原选型稿写“按论文复现”就从零另造近似算法。

实施步骤：

1. 锁定兼容运行环境，验证 `causalnex.structure.dynotears.from_pandas_dynamic` 的示例。无法直接安装时只做有数值对照的兼容迁移，记录改动。
2. 输入与 PCMCI+ 相同的设备序列。方法不原生支持所需 mask 时，使用真实连续可观测片段或判不适用；不能静默填零。标准化遵守逐例推断或训练统计的已声明协议。
3. 保留同期矩阵 W 和滞后矩阵 A，以及拟合损失、收敛状态、无环残差。固定最大滞后、两类正则化、边门限与优化预算。参数搜索不得使用测试图标签。
4. 根据 `var_lagk → other_lag0` 解析来源及目标，跨滞后支持默认取绝对系数最大值，符号单独保存。负系数不是反向边；选择绝对系数是本实验输出适配，并非异常传播概率。
5. 时间展开图中的无环约束不能保证折叠设备后无环，折叠后的双向/环由公共适配器处理。报告同期和滞后原生关系分布及适配损失。

验收：与锁定作者实现对同一小样本数值输出相符；正确处理滞后方向和自回归；不把“未收敛”写成有效零边输出；Root/自主 Full 为不支持。

## 10. A7：TCDF-Graph + device adapter

来源：[作者实现](https://github.com/M-Nauta/TCDF)、[核心代码](https://raw.githubusercontent.com/M-Nauta/TCDF/master/TCDF.py)。必须保留注意力卷积网络、候选原因选择、PIVM 验证与时延提取，不能只取注意力 Top-K。

每例、每目标设备运行原生图发现，统一感受野、层数、kernel、dilation、学习率、epochs、significance 和随机种子；预算依据开发集冻结。网络训练属于每例诊断开销。计数序列迁移仍受 A4 条件约束。

特别检查作者 `causeswithdelay[(targetidx, v)]` 的返回约定：该键表示目标与原因，设备边应为 `v → targetidx`，不可按元组顺序反着写。保存候选原因、验证后原因、时延、原始注意力及损失；只把验证后方向映射到设备，统一适配器的排序规则单独声明。注意力及 PIVM 输出都不冒充归一化概率。

验收：用明确 A 导致 B 的合成序列检查输出方向；验证剔除的关系不能重现于最终图；核对感受野覆盖所设最大时延；Root/自主 Full 为不支持。与 PCMCI+/DYNOTEARS 比较时使用同一 A4 数据版本，资源不足或不收敛要计入失败记录。

## 11. A8–A10：条件候选的实施边界

### A8 REASON

来源：[作者正式论文](https://nijingchao.github.io/paper/kdd23_reason.pdf)，正式题名 *Interdependent Causal Networks for Root Cause Localization*，KDD 2023。

先交输入审计：高低层实体是否真实存在、每层是否有对应观测、系统 KPI 是否为可对齐的序列。设备型号、网络 hop 层和人为分组不能不经说明就替代原实体层级；单个 `cross` 汇总值或“Pingmesh 异常”标志也不能替代 KPI 流。

条件成立后，按原文实现层内/层间关系学习、图上的排名、自身异常分数及其融合；保存分项分数，不能用 PageRank 等新排序器替换原流程。最先验收 Root。原生因果邻接仅作机制图诊断，图任务暂不启用；如要研究它的事故传播迁移，必须另定义当前事故的关系选择规则、命名组合方法并接受独立审查，不能直接用邻接矩阵算 Full-Graph。

代码来源本轮未确认完整作者实现；可从论文机制复现，但要逐模块附实现对应说明。验收检查跨层映射、变量对齐、KPI 方向、常量/缺失序列及冻结参数，不允许通过删掉层间机制把方法变成普通单层图学习。

### A9 CORAL

来源：[作者预印本](https://arxiv.org/abs/2305.10638)，正式 KDD 2023 题名 *Incremental Causal Graph Learning for Online Root Cause Analysis*（DOI 10.1145/3580305.3599392）。

启动条件是连续实体观测、KPI 流、前置历史/初始状态图和可持续对应的实体身份。正式实现须保留状态变化检测、前一状态缓存、增量因果图学习和原生排名；若采用 Pingmesh 外部触发，明确命名 `externally-triggered CORAL-adapt` 并披露替换的模块。

采用时间顺序协议，每次更新记录截止时间、前一状态和新图；来自未来窗口的数据不能进入当前缓存。逐事故无标签更新是被允许的算法步骤，和利用全测试库训练后回评有本质区别。状态因果图不是自动成立的单根事故传播图，第一版只承诺条件 Root 与原生图诊断。

本轮未确认作者完整实现，论文引用的通用因果工具不等于 CORAL 代码。若缺连续背景，不生成伪正常前缀，不把随机事故拼流；交付条件不满足报告。验收重点为时间因果性、状态重置、触发器执行、增量更新及排名机制一致。

### A10 NetCause

来源：[作者正文](https://arxiv.org/html/2606.13543v1)。作者 PDF 首页标注已被 ICCCN 2026 接收，当前查阅的是作者预印本。未确认官方代码仓库。

它是强根因定位近邻，值得优先输入审计。需核对故障/操作的状态开启与解除、impact 节点和时间、关系类型，以及事故前后可观察范围。原法输出候选状态转移排名；设备级结果需要聚合，图列不自动成立。

实施顺序：

1. 由输入构造异构拓扑和状态张量；没有动作/逻辑层级时删除相应维度并记录，不填全零冒充观测正常。只有告警出现脉冲而不能恢复状态时，应另命名 `NetCause-event-occurrence-adapt`，先审查其偏离程度。
2. 按论文实现空间编码、时序模型和下一状态预测，训练仅用训练事故；不能拿简单监督根分类替代传播预测。
3. 枚举预测时可得的候选转移，逐一进行论文定义的干预和 rollout，计算 TCI。干预变量、保持固定的观测、rollout 时间范围和影响聚合域逐项锁定；遇到论文没有写清的细节，写明工程选择。
4. 首版设备分数取该设备合格转移 TCI 的最大值；没有合格转移的设备记为原生不可评分并保留覆盖统计。候选构造不能事先保留真根。
5. 只输出 Root 排名及转移级明细，另记录 factual/counterfactual 结果、候选数和开销。物理图上的 GNN 消息权重或反事实作用分数不能直接当作设备传播边。

验收：空干预产生零差（随机仿真用配对随机数及误差容差）；逐候选与批量干预一致；未来数据和测试标签不影响结果；同设备多转移聚合确定；没有影响时间或状态语义时明确不适用。

| `full_link.alarm_list` | 样例有 `alarm_time/occur_time/alarm_id/alarm_name` 等，先确认两个时间的定义和单位；设备归属用真实对象字段验证 |
| `full_link.log_list` | 当前样例只看到 `total` 汇总字段；计数不能还原带时间/设备的日志事件，更不能复制出虚构日志 |
| `full_link.task_trace` | 一例非空、一例为空；有 `trace_route_hops/src_mgmt_ip/dst_mgmt_ip`，先审计测量时刻与覆盖；不能默认是完整 ECMP 精确路径或微服务调用 trace |
| `full_link.cross` | 含 `cross` 和 `probability_calibration` 等；核对哪些是观测计数、哪些是已有诊断模型输出，未确认前不整体当作原始事实输入 |
| `full_link.groud_truth` | 原始拼写如此；只进入独立标签通道，禁止透传给 baseline |
| 告警 `score`、其他预计算分数 | 需证明其来源及预测时可获得性；不能因字段已存在就允许作为纯观测输入 |

因此公共 `endpoint_context` 必须是字段白名单对象，不能是原 `full_link` 或 `task_info` 的任意字典复制。以上仅说明标签和派生诊断字段可能与观测共存，并不等于已证实它们进入现有模型造成泄漏。

`Sys/Score/evaluate_propagation.py` 当前 `_label_edges` 把 `definite/possible` 合为正例，`_set_scores` 用预测集与参考集直接算分；该实现不能仅凭文稿描述就视为已经支持未知边 mask。A0 要先核对 `possible`、`unknown`、允许边、必需边和完整标注的含义，生成版本化转换和专用测试；不得私自把原标注语义统一改写成负例或必需正例。

本次本机 `data/node` 无完整案例集，`data/raw/pingmesh_labeled` 可见两个原始 JSON，不能据此确认全量案例数量、单根标签质量或可用时间序列比例。历史文档中的实验案例数不作为这次数据审计结果。A0 应在实际实验数据位置运行完整审计，并把缺失数据的结论与方法不适用区分开。
