## R2 — 多端点症状没有推出多设备传播（P1）

### 核对

验收的物理判断是对的：**单一共享设备或链路的故障同样能让多对端点同时异常**。
初稿 §2.1 第①行写"共享 → 影响表现为同一窗口内多对端点的探测异常"，第②行直接从
"端点异常"跳到"不指示设备之间的关系"；§2.2 草稿写"**很少**只影响一条链路"——
这既是频率断言（无依据），也隐含了"多症状 = 多传播"。

同时确认初稿存在验收指出的内部矛盾：§2.5 第 3 行要求"端点异常覆盖统计"，
而 §2.5 末段又写"上表三项都是**写作材料**"——**覆盖统计是描述统计，不是写作材料**。

## R4 — 最近邻泛化、ODNS"自证"、泄漏推断（P2）

三条**全部成立**：

1. **"现有工具无法说明关系"过宽**。合同已记录 `NetEventCauseDevice` 支持 graph/Full，
   `PCMCI+` / `DYNOTEARS` 支持 Oracle/Shared 图任务——**这些方法能产出图**。
   初稿 §2.4 的"需核实的最近邻能力"实际只写了本项目评分器，没有核实最近邻。
2. **ODNS 的"方法—评价自证"**：核对 `www25-odns.txt` 第 174–178 行，受控 ADNS 与唯一 A 记录
   首先是它的**测量机制**（用缓存足迹给解析器打标签）。仅因测量由作者构造就断定循环论证，
   依据不足——[T005 验收](../../../../.ai/T005_acceptance.md) R6 已指出同一问题，
   我在新稿里又引了一次。
3. **泄漏推断**："材料由看过标签的人整理"不是泄漏的充分条件。可检查的是
   **材料是否含测试答案**、**是否被用于筛例/构造输入/调参/选择结论**。

### 改动（迁移报告 §2.4）

- 差异论证**限定为 root-only 输出**，并显式写明"不能泛化为现有工具都无法说明关系"，
  同时点名合同里已有的 graph/Full 与 Oracle/Shared 能力。
- **撤回 ODNS 的"自证"判断**，改为"**其标签生成与独立验证的关系本轮未查清，
  记为验证边界待查**"。
- 新增 **N1–N5 核实清单表**：原生输出 / 事件到设备投影 / 输入资格 / 方向语义 / 根条件。
- §2.5 数据边界改为"材料是否含测试答案、是否用于筛例/输入/调参/选择结论"。
