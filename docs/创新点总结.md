# Pingmesh 根因定位与传播路径重构创新点总结

> 记录日期：2026-08-19  
> 本文档先保留讨论形成的初始提纲，再给出结合当前 PC-STGR、PC-STGR-SSL 和 Stage 2 实现补充后的论文表述。

## 1. 初始提纲

1. 针对生产故障 case 数量少、根因标注成本高、监督训练容易过拟合的问题，采用自监督学习。
2. 针对拓扑、告警语义和设备状态关联复杂的问题，现有方法存在不足，需要说明本文采用的方法。
3. 针对黑盒方法虽然能够快速输出根因结果、但缺乏解释性的问题，需要说明解释性在工程实践中的重要性，并据此提出传播路径重构 Stage 2。
4. 针对告警缺失、时间重叠、语义冲突以及 ECMP 导致传播方向难以确定、无法直接判断两个设备之间故障传播方向的问题，采用三状态概率建模以简化问题。
5. 针对三状态概率图的求解困难，需要说明困难来源以及本文采用的求解方法。

## 2. 补充后的总体逻辑

| 编号 | 工程挑战 | 现有方法的主要不足 | 本文方法 |
| --- | --- | --- | --- |
| 1 | 故障 case 少、人工根因标签昂贵，监督信号稀疏 | 仅依赖 case 级根因标签训练，容易记忆少量 case 的特定模式并产生过拟合 | PC-STGR-SSL 利用图内设备、事件和边构造掩码与重构任务，先进行无标签预训练，再进行根因排序微调 |

## 3. 扩写后的创新点

### 创新点一：面向少标注生产故障的图内自监督预训练

**工程挑战。** 生产网络中的有效故障 case 数量有限，根因标签需要运维专家结合多源数据进行人工确认，获取成本高。当前每个 case 只提供一个 case 级根因标签，分组训练后可用的监督 case 更少，直接训练图神经网络容易记忆特定告警组合、端点位置或拓扑模式，从而产生过拟合。

**本文方法。** 提出 PC-STGR-SSL，利用单个 case 内丰富的 Device 节点、Event 节点和关系边构造无标签预训练任务，包括事件名称掩码恢复、节点数值特征重建以及边存在性与关系类型重建。模型首先通过这些任务学习告警语义、设备状态和图结构依赖，再使用少量 case 级根因标签进行设备排序微调。分组 OOF 中，自监督预训练语料和事件词表均限制在当前训练折内，避免相似 case 或事件词表造成验证信息泄漏。

**创新价值。** 该方法不是将同一 case 中的大量设备节点错误地视为相互独立的根因标注样本，而是将图内部的节点、事件和边转化为密集的自监督约束，在不增加人工标注成本的情况下提高有限 case 的信息利用率，并为后续根因排序提供更稳健的编码器初始化。

### 创新点二：面向复杂异构观测的路径条件化 Device–Event 时空图排序

**工程挑战。** Pingmesh 只能给出异常源端和目的端，实际根因同时受到设备在源—目的路径中的位置、物理拓扑连接、设备告警状态、告警语义以及跨设备事件先后关系影响。这些因素存在明显的结构依赖和非线性交互，难以通过单一统计量准确表达。

**现有方法不足。** 基于人工规则或固定权重的排序方法通常先分别计算拓扑分数、时间分数和告警分数，再进行线性融合，难以学习不同 case 下各类证据之间的动态关系。Device-only 图模型则需要先将设备上的多条事件压缩为统计特征，容易丢失事件归属、事件语义和细粒度时间顺序；将所有特征直接输入普通分类器又无法显式利用物理邻接和事件关系。

**本文方法。** 提出 PC-STGR，将设备和告警/日志事件分别建模为 Device 节点和 Event 节点，将异常端点距离、近最短路径走廊和端点锚点写入设备特征，并显式构造物理拓扑、事件归属、设备内时间顺序和跨设备时间关系。关系感知多头图注意力在不同关系上完成证据传播，最终通过 case 内 Softmax 直接学习当前故障中的设备根因排序。

**创新价值。** 该方法的创新不在于提出新的通用注意力算子，而在于将 Pingmesh 路径条件、事件级语义和显式时空关系统一到 Device–Event 图中，并将其适配为候选集合随 case 变化的设备级排序问题。

### 创新点三：面向工程可核验性的两阶段传播解释框架

**工程挑战。** 学习式模型能够快速输出根因设备及其概率，但单一排名分数难以说明“故障从哪里开始、经过哪些设备、最终影响了哪些观测节点”。模型即使预测正确，也可能依赖偶然相关性；预测错误时，运维人员也难以判断错误来自告警噪声、拓扑理解还是传播方向判断。

**解释性的重要性。** 在生产网络中，根因定位结果通常会影响端口隔离、设备切换、路由调整和故障域控制等操作。运维人员需要根据原始告警和物理拓扑核验诊断结果，评估影响范围，并选择风险可控的处置位置。可回溯的传播路径还服务于跨团队协同、变更审计和事后复盘。因此，仅给出设备分数或模型注意力权重不足以满足工程决策要求。

**本文方法。** 在 Stage 1 根因候选排序之后增加传播路径重构 Stage 2：M1 根据拓扑、时间、告警语义和直接邻居证据形成根因无关的概率传播图；M2 再以不同候选根因为条件生成对应的传播 DAG，并保留节点和边到原始告警、日志及物理拓扑边的证据映射。

**创新价值。** 该框架将“快速候选定位”和“可核验传播解释”解耦后再联合：Stage 1 保证候选召回和推理效率，Stage 2 给出结构化传播依据，并利用传播解释反向检验候选根因，使最终结果既包含根因设备，也包含可供工程人员核验的故障演化过程。

### 创新点四：面向局部方向不确定性的三状态概率传播建模

**工程挑战。** 告警可能缺失或延迟，不同设备的时间区间可能重叠，同一组告警语义可能支持相反方向，ECMP 和高扇出拓扑还会使真实转发路径不可见。因此，对两个物理相邻设备直接判断唯一的故障传播方向往往缺乏充分证据。

**现有方法不足。** 将相邻设备关系直接硬判定为 `A→B` 或 `B→A`，会强迫系统在证据不足时给出方向，并彻底丢弃另一方向及“不存在直接传播”的可能性。一旦局部硬判定错误，后续路径搜索会沿错误方向持续扩展。另一方面，直接在全网范围同时枚举所有传播结构，求解空间过大，也不利于证据回溯。

**本文方法。** M1 将全局问题分解为物理相邻设备对上的局部三状态估计。对于每一对设备，融合带容忍区间的事件先后证据、告警语义组合和本端/远端邻居描述，输出：

```text
P(A→B), P(B→A), P(No Direct Propagation)
```

拓扑只用于限定需要评价的相邻设备对，不直接为某个传播方向加分；Stage 1 候选排名和候选根距离也不进入边概率计算。证据不足或缺少动态传播支持时，模型可以提高“无直接传播”概率，而不被迫选择一个方向。

**创新价值。** 三状态建模将难以直接确定的因果方向转化为带不确定性的局部概率关系，既保留正反方向竞争，又显式描述边未激活的可能性。所有根因候选共享同一张根因无关概率图，从而避免“根据候选根因生成路径，再用该路径证明候选根因”的循环论证。

### 创新点五：三状态概率图上的根因条件化约束路径求解

**求解困难。** 三状态概率图中的边概率是相互独立的局部判断，不能通过逐边选择最大概率状态直接得到传播路径，主要困难包括：

1. 正反方向概率接近时，局部图会同时保留双向候选边；
2. 独立边组合可能形成有向环，违背从根因向外传播的解释结构；
3. 高扇出拓扑中存在大量分支和替代路径，根因到多个异常目标的路径组合会快速增长；
4. 高概率边不一定从候选根因可达，也可能与根因向外传播的方向相反；
5. 低质量或缺乏原始拓扑依据的边可能连接成表面得分较高、实际不可执行的伪路径。

**本文方法。** M2 采用“局部概率建模—根因条件化求解”的分层策略。对 Stage 1 中的每个候选根因分别执行：

1. 使用原始拓扑边标识校验候选传播边，删除无法映射到本次 case 物理拓扑的关系；
2. 计算设备相对候选根因的拓扑距离，仅保留从根因向外、方向概率高于“无直接传播”概率且达到支持阈值的有向边；
3. 以异常设备为目标，在路径深度和搜索宽度约束下进行束搜索，综合边的最低概率、平均概率、目标证据、证据可回溯性、矛盾项和路径复杂度选择候选路径；
4. 将不同异常目标的高分路径进行合并，对会产生有向环或替代关系冲突的路径进行拒绝，形成根因可达、拓扑合法且全局无环的传播 DAG；
5. 计算该根因选中边概率占全部有效传播关系概率的比例，作为传播解释性得分，并与 Stage 1 得分联合生成最终根因排名；传播证据不足时回退到 Stage 1，避免无依据重排。

**创新价值。** 该方法将局部方向不确定性的估计与全局传播结构生成分开处理，通过可控的约束搜索解决双向竞争、环路和组合爆炸问题，同时支持多目标和分叉传播。本文采用的是可复现的约束束搜索与 DAG 合并策略，不宣称获得组合优化意义上的全局最优解，其优势在于满足生产诊断所需的拓扑合法性、根因可达性、证据可追溯性和计算可控性。

## 4. 五个创新点的一句话版本

1. **少样本自监督：** 将 case 内丰富的设备、事件和边转化为掩码与重构任务，在不增加根因标注成本的情况下预训练 PC-STGR 编码器，缓解少量生产故障 case 上的监督过拟合。
2. **异构时空排序：** 构造融合异常路径位置、设备拓扑、事件语义和时间关系的 Device–Event 图，弥补规则融合和 Device-only 模型难以表达细粒度跨信号关联的问题。
3. **工程传播解释：** 在黑盒根因排名之后重构证据可回溯的故障传播图，为诊断核验、影响范围评估、处置决策和事后复盘提供结构化依据。
4. **三状态概率图：** 将难以硬判定的设备间传播关系表示为“正向、反向、无直接传播”三状态概率，在简化局部建模问题的同时保留方向不确定性。
5. **约束路径求解：** 通过根因条件化过滤、逐目标束搜索和无环路径合并，将局部三状态概率转化为拓扑合法、从根可达的传播 DAG，并利用其解释能力联合优化根因排序。
