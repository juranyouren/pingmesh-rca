# INFOCOM Introduction 论证稿

更新日期：2026-07-11

## 1. 一句话主张

> Pingmesh 已经给出受影响端点和故障参考时间；根因设备定位的关键不是继续扩大观测，而是用这两个事件条件约束可行物理路径，并用抗告警量偏差的时间证据交叉验证，在固定证据不可识别时选择性推理或拒判。

## 2. 推荐段落结构

### 第 1 段：背景与任务入口

大型云业务依赖数据中心网络的低时延与高可用。Pingmesh 一类端到端测量系统能够持续发现丢包和时延异常，并给出受影响的 source、sink 及触发时间；但告警触发后，运维仍需从数百台 Clos 设备及其告警和日志中确定真正故障设备。这个定位步骤直接决定故障缓解时间，也是本文研究的任务，而不是再次进行异常检测或告警聚合。

### 第 2 段：工程现象/任务特点

该任务具有三个相互耦合的工程现象。第一，ECMP 使一个端点对对应多条等价路径，Pingmesh 异常不能唯一确定实际经过的物理设备；故障还会沿网络依赖传播，使大量非根因设备出现症状。第二，告警出现时间会因检测、上报和级联传播而漂移，症状设备甚至可能比根因设备更早或产生更多告警。第三，每个 case 同时包含拓扑、告警、日志和描述文本；全量语义推理会放大噪声、上下文和时延。因而，“告警最多”“全图最中心”或“最早告警”都不能单独作为可靠根因指标。

### 第 3 段：最接近的路径/拓扑方法及缺口

网络层析从端到端路径结果推断内部节点状态，为本任务提供了最接近的形式化视角。PROTON 在部分可观测和不可控路由下用路径结果近似设备失效概率，D2NeT 进一步通过分布式、主动选择的路径探测减少不确定性；Hawkeye 和 SkeletonHunter 则用 PFC provenance 或训练流量骨架缩小定位空间。这些方法证明了路径约束的重要性，但它们要么可反复选择新的二值路径观测，要么依赖普通 Pingmesh case 中不存在的专用 provenance/工作负载结构。ECMP 等价绕路和灰故障也使单一路径的工作/失败抽象不可靠。因此，本文需要在固定事后证据上计算 source-sink 可行路径支持，而不能直接复用主动层析或把全图中心性称为因果传播。

### 第 4 段：事件相关方法及缺口

另一类方法从告警事件中恢复依赖关系。COLA 结合历史相关性挖掘与 SOP-aware LLM，NetEventCause 用 temporal point process 和 attribution 推断 root/derivative alarms，SkyNet 按时间与位置组织层次告警树。这些方法有助于压缩事件量并提供时间或语义关系，但把它们直接转换为设备排名会产生三个问题：告警丰富的症状设备可能支配相关模式；长尾和新告警缺少历史支持；事件相关无法证明设备位于当前端点对的可行影响路径。因此，事件证据应在物理路径约束下使用，并显式抑制重复告警量。

### 第 5 段：因果图/LLM 方法及缺口

近期 RCA 系统进一步使用因果图和 LLM 处理异构证据。NRCAC 用 eBPF 与领域知识约束微服务因果图；BiAn 通过告警摘要、设备分析、拓扑和时间线多流水线输出故障设备；TAMO 用专用工具把多模态数据转换为可供 LLM 使用的诊断表示。这说明语义推理适合组织知识和处理冲突，但效果依赖丰富遥测、可识别的因果变量和专门工具。对每台设备执行无约束 LLM 推理既昂贵，也可能任意选择证据或覆盖正确排序。本文实验中，全量 LLM 重排 Top-1 为 75.47%，没有超过确定性融合的 76.10%，进一步说明 LLM 不应成为默认主排序器。

### 第 6 段：核心 insight

我们的核心观察是，一台可信根因设备应同时满足两种相互独立的解释：它在当前 source-sink 事件所允许的物理路径中具有足够支持，并且其异常事件相对故障参考时间呈现与根因一致的 onset，而不是仅凭告警数量获胜。拓扑/路径证据解决“它是否可能影响该端点对”，时间证据解决“它是否可能发起而非仅响应异常”。当两者一致时，确定性结果可直接接受；当两者冲突或固定观测不可识别时，才需要语义仲裁或人工复核。

### 第 7 段：三个挑战

实现上述思路面临三个挑战。**C1：路径-时间传播歧义。** ECMP 产生多条可行路径，Clos 中心设备容易获得虚高结构分数，而告警洪泛又会扭曲时间统计。**C2：语义证据预算。** 端口、物理链路状态和原始时间是关键证据，但重复告警与无关日志会稀释它们。**C3：准确性、时延与可诊断性的平衡。** 系统既不能让昂贵 LLM 处理所有 case，也不能在证据不足时强制输出高置信结果。

### 第 8 段：三个模块一一对应

针对 C1，我们设计 **Incident-Conditioned Path-Temporal Localization (ICPTL)**：由端点构造可行路径走廊，按设备对异常路径的支持度聚合拓扑证据，并用角色/度归一化与去重相对 onset 抑制中心性和告警量偏差。针对 C2，我们设计 **Semantic Evidence Canonicalization Layer (SECL)**：确定性保留最早事件、最高严重度、接口/物理链路描述及来源指针，在固定预算内生成可追溯证据；小模型只作为可选文本渲染器。针对 C3，我们设计 **Selective Root Cause Localization (SRCL)**：接受一致的高置信确定性排序，仅对冲突 case 调用 LLM，并对低可诊断 case abstain 交由人工复核。

> 注意：当前代码只实现告警感知 PageRank、burst/early-bird/density 和等权融合。只有在完成路径走廊、角色/度归一化、告警去重/相对 onset、可靠性融合及相应消融后，论文才能使用上一段的完整现在时表述。提交前若尚未实现，应改为“we are developing”或缩回当前机制，不能只做命名包装。

### 第 9 段：结果

我们在 159 个生产 Pingmesh 故障 case 上评估当前确定性基线。拓扑证据单独取得 50.31% Top-1，时间证据单独取得 62.89%，二者等权融合达到 76.10%，相比最强单视角提高 13.21 个百分点，说明两类证据具有真实互补性。完整方法还应报告 held-out Top-K、置信区间、选择性覆盖/风险、LLM 调用率、人工复核率、token 和时延；在这些实验完成前，不应声称门控或摘要提高最终准确率。

### 第 10 段：贡献

增强实现完成后，贡献可写为：

1. 我们形式化 Pingmesh-triggered physical device localization，揭示 ECMP 路径歧义、Clos 中心性偏差和告警量偏差如何共同使事件热点偏离物理根因。
2. 我们提出 ICPTL，用事件条件化的可行路径支持和抗告警量时间证据定位候选设备，并输出固定观测下的可诊断性。
3. 我们提出 provenance-preserving evidence budgeting 和 selective reasoning，在确定性一致时直接输出、冲突时语义仲裁、证据不足时拒判。
4. 我们在生产故障上通过单视角消融、路径/时序组件消融、held-out 门控校准、效率与失败案例分析验证方法。

当前实现若不增强，贡献必须缩为：

1. 将 Pingmesh 触发后的诊断形式化为物理设备 Top-K 排序，并构建无标签泄漏的 159-case 评测流程。
2. 实证说明拓扑与时间证据互补，当前简单融合较最强单视角提高 13.21 个百分点。
3. 通过全量 LLM 重排的负结果，论证选择性语义仲裁比默认 LLM 主排序更合适。

## 3. 与 COLA 写法的对应关系

COLA 的 Introduction 不是先列模块，而是按如下顺序推进：生产可靠性背景 -> 告警风暴现象 -> 两类既有方法及各自失败模式 -> 引入知识/LLM 的动机 -> 三个落地挑战 -> 三个对应设计 -> 生产结果和贡献。

本文可复用这个论证节奏，但不能复用它的任务分类：

- COLA 的“语义相似 vs 统计相关”替换为本文的“路径约束 vs 事件依赖 vs 受控语义推理”。
- COLA 的核心知识是 SOP；本文的核心事件条件是 source、sink 和故障参考时间，核心领域约束是物理 Clos/ECMP 可行路径。
- COLA 让 LLM 处理低置信告警对；本文让 LLM 处理低置信设备排序冲突。
- COLA 评价 alert-pair F1；本文评价 device Top-K、selective risk/coverage 和诊断成本。

## 4. 当前大纲需要修改的关键点

1. 把“时空传播复杂性”具体化为“ECMP 可行路径歧义 + Clos 中心性偏差 + 告警 onset/volume 偏差”，否则挑战过泛。
2. DDFL 更名或至少在技术层命名为 ICPTL；“设备确定性聚焦”描述架构作用，但没有说明 INFOCOM 关心的网络机制。
3. SECL 不写“轻量语义压缩提升定位”，改写为“可追溯证据规范化与预算控制”，并把准确率设为 non-inferiority 指标。
4. SRCL 不只写“平衡时延与复杂推理”，还要引入 diagnosability/abstention，并用 coverage-risk 曲线评价。
5. 现有方案顺序改为路径约束 -> 事件依赖 -> 因果图/LLM，最接近任务的方法应最先讨论。
6. 实验段只使用 159-case 无泄漏结果；不要使用历史受泄漏影响的 87% 数字，也不要把 75.47% LLM 重排写成提升。
