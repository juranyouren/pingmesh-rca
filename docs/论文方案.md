# Pingmesh 故障治理方案

> 本文根据 `pingmesh治理.pptx` 的文字内容整理，用于后续查阅与方案沟通。
> 文档仅保留当前采用的两阶段方案；旧版 IC-STGR、旧的并列分支及迁移过程不再作为现行方案描述。

## 1. 背景与目标

### 1.1 Detection is not Diagnosis

大型数据中心网络广泛采用 Clos 和 ECMP。一处链路、设备或协议异常，可能同时影响多条业务流，最终表现为端到端时延升高或丢包。

Pingmesh 能够持续探测源端到目的端之间的网络质量，及时发现受到影响的端点对，但它解决的是异常检测问题，不能直接完成生产环境中的故障诊断。

当前诊断面临两个核心问题：

1. **端到端异常无法直接映射到物理根因。** 在缺少路径级遥测的情况下，ECMP 使流量实际经过的内部路径不可见，因此端到端症状无法直接对应到具体设备。
2. **得到根因候选不等于完成诊断。** 运维人员还需要分析故障影响链，梳理候选根因如何影响其他设备和端到端异常，区分根因告警、派生症状与偶然共现的异常，并核验该候选是否能够解释分散出现的异常。

因此，Pingmesh 故障治理系统不仅需要回答“哪个设备最可能是根因”，还需要提供一条能够组织分散观测、反映故障影响过程、并可供运维人员核验的传播解释。

### 1.2 方案目标

本方案联合完成两项任务：

- 对候选设备进行根因排序，输出高召回的 Top-K 候选；
- 对候选根因进行传播验证，输出可回溯的故障传播图，并辅助验证和重排根因候选。

## 2. 现有方案与研究缺口

### 2.1 增强观测后进行物理定位

代表方法包括 R-Pingmesh、Canary、Hawkeye 和 SkeletonHunter。这类方法通过更细粒度的主动探测、数据平面遥测、路径编码或机制专用信号，提高故障物理位置的可观测性。

**局限：**大规模存量网络面临部署成本、设备兼容性与覆盖限制；没有预先采集的路径证据也无法在事后恢复。

### 2.2 从历史故障中学习根因模式

代表方法包括 Eadro、DiagFusion 和 GAMMA。这类方法利用深度学习，从指标、日志、Trace、告警和系统依赖关系中学习故障特征，并据此定位根因组件。

**局限：**数据驱动方法需要数量充足且具有代表性的故障样本，但生产故障 case 数量少，根因标签获取成本高。

### 2.3 聚合多源证据进行根因排序

代表方法包括 TraceRCA 和 MicroRank。这类方法根据异常程度、组件依赖和统计关联，对不同组件进行打分和排序，从而缩小根因排查范围。

**局限：**在数据中心网络中，同一告警出现在不同拓扑位置可能具有不同含义，事件时间与告警语义也会相互影响。人工规则、固定权重和简单统计关系难以表达随路径和 case 变化的复杂交互。

### 2.4 重构事件关系以提供诊断解释

代表方法包括 MULAN、FaultInsight 和 NetEventCause。这类方法通过因果发现或事件时序建模，恢复指标、告警或异常事件之间的关系。

**局限：**实际观测可能存在告警缺失、上报延迟、时间重叠和语义冲突，不同证据还可能支持不同的传播方向。因此，局部事件关系可能不稳定，也难以进一步组成一条完整、连贯且能够解释当前故障的影响链。

## 3. 核心挑战

### 3.1 Sparse Cases with Dense Information

故障 case 数量少，根因标签获取成本高；但单个 case 内包含大量设备、事件和关系。图中节点多，并不意味着存在大量相互独立的根因样本。

如果仅依赖少量 case 级标签训练，模型容易记忆特定端点组合、告警模式或拓扑结构，并在新 case 上产生过拟合。

### 3.2 Root-Cause Rankings with Limited Diagnostic Verifiability

根因排名只能回答“谁更可疑”，不能说明该候选如何造成当前异常，也不能直接为运维人员提供故障影响链分析。

### 3.3 Multidimensional Evidence with Complex Interactions

多源证据之间存在复杂交互：

- 人工规则、固定权重或简单聚合难以充分建模这些交互；
- 设备故障之间的传播关系无法依靠单一证据直接判断。

## 4. 关键观察

### 4.1 Case 级标签稀疏，不等于 case 内学习信号稀疏

设备属性、事件语义、物理邻接、事件归属，以及设备内和跨设备的时间关系，都可以转化为图内自监督学习信号。

这意味着模型可以在缺少大量 case 级根因标签的情况下，利用单个 case 内部的密集结构学习设备、事件和关系表示。

### 4.2 可信根因应当形成可核验的故障传播图

可信根因应当能够在当前 case 中形成一张可解释大部分异常现象的故障传播图。

局部传播方向可以保留不确定性，但最终解释必须在全局上满足以下条件：

- 拓扑合法；
- 从候选根因出发可达；
- 传播结构无环；
- 每条传播关系的证据可回溯。

## 5. 两阶段总体框架

整体流程如下：

1. 输入 Pingmesh 异常端点、物理拓扑、告警、日志和时间戳；
2. Stage 1 构造路径条件化的 Device-Event 时空图，学习根因候选；
3. Stage 1 输出设备级根因概率和 Top-K 候选；
4. Stage 2/M1 对物理相邻设备进行三状态传播概率建模，形成共享的局部传播假设图；
5. Stage 2/M2 分别以每个候选为根，在全局约束下生成候选根因对应的传播 DAG；
6. 根据候选解释全局观测的能力，验证并重排 Stage 1 结果；
7. 输出最终根因排名、主故障传播图和原始证据映射。

## 6. Stage 1：Candidate Learning

### 6.1 图内自监督预训练

Stage 1 通过图掩码自监督预训练，利用单个 case 内密集的设备、事件和关系，缓解 case 数量少、根因标签稀疏的问题。

### 6.2 路径条件化 Device-Event 时空图

将设备和事件构造成异构图，并联合建模：

- **拓扑信息：**设备之间的物理邻接与路径位置；
- **语义信息：**事件类型、事件内容和事件归属；
- **时序信息：**设备内和跨设备的事件先后关系；
- **Incident 条件：**当前 Pingmesh 异常端点及其路径上下文。

### 6.3 PC-STGR 根因排序

PC-STGR 使用异构图和多头注意力机制学习设备表示，输出设备级根因概率和 Top-K 候选。

实验中使用两个版本：

- **PC-STGR：**不加入图掩码自监督预训练的基础版本；
- **PC-STGR-ssl：**加入图掩码自监督预训练的完整版本。

## 7. Stage 2：Propagation Verification

Stage 2 不再停留在“根因排序”，而是检查每个候选根因能否形成一张拓扑合法、方向一致、证据可回溯的故障传播图。

### 7.1 M1：根因无关的三状态概率建模

对每一对物理相邻设备 A、B，估计三个互斥状态：

```text
P(A -> B)
P(B -> A)
P(No Direct Propagation)
```

M1 保留局部传播方向的不确定性，并为所有根因候选建立一张共享的局部传播假设图。该阶段不预设根因，也不根据 Stage 1 排名改变局部传播关系。

### 7.2 M2：根因条件的全局传播求解

M2 分别以每个 Stage 1 候选为根，在以下约束下生成传播假设 DAG：

- 传播边必须存在于物理拓扑；
- 传播方向必须与 M1 的概率判断兼容；
- 异常节点必须从候选根因可达；
- 最终传播结构必须无环。

每条传播边都保留与原始事件证据的映射。M2 再根据候选根因对全局观测的解释能力，对 Stage 1 结果进行验证和重排。

### 7.3 输出

Stage 2 最终输出：

- 最终根因排名；
- 每个候选根因对应的传播图；
- 最终 Top-1 根因对应的主故障传播图；
- 传播边到原始告警、日志和时间证据的映射；
- 无法确定的局部传播方向和未解释异常。

## 8. 实验结果与实验计划

### 8.1 Stage 1 实验结果

| 方法 | 技术类型 | Top-1 | Top-3 | Top-5 |
| --- | --- | ---: | ---: | ---: |
| Topology-only | 告警感知 PageRank 与拓扑距离 | 50.31% | 74.21% | 84.28% |
| Temporal-only | burst、early-bird、density | 62.89% | 88.05% | 94.34% |
| Deterministic Fusion | Topology 与 Temporal 等权融合 | 77.36% | 89.94% | 94.34% |
| PC-STGR | Incident 条件化异构时空图排序 | 73.58% | 93.71% | 97.48% |
| PC-STGR-ssl | Incident 条件化异构时空图排序 + 自监督预训练 | 77.36% | 93.71% | **98.11%** |

结果表明：

- PC-STGR 和 PC-STGR-ssl 的主要收益体现在 Top-3、Top-5 候选召回；
- PC-STGR-ssl 的 Top-1 达到 77.36%，与 Deterministic Fusion 持平；
- PC-STGR-ssl 的 Top-5 达到 98.11%，是当前表中最高结果；
- Stage 1 的目标是尽可能将真实根因保留在 Top-K 中，为 Stage 2 的传播验证和候选消歧提供空间。

### 8.2 Stage 2 概率方法

| 实验 ID | 概率方法 | 说明 |
| --- | --- | --- |
| P0 | 加权确定性计算 | 使用人工定义的证据权重计算三状态概率，作为确定性基线 |
| P1 | 三状态 Logit/Softmax | 分别计算两个传播方向和无直接传播的 logit，再进行 Softmax |
| P2 | 监督式 Edge Classifier | 训练小型分类模型，对每个物理相邻边进行三状态分类 |

## 9. 当前方案边界

### 9.1 现行主方案

- Stage 1：PC-STGR-ssl 根因候选学习；
- Stage 2/M1：根因无关的三状态传播概率建模；
- Stage 2/M2：根因条件的全局传播 DAG 求解、验证与重排。

### 9.2 仅作为实验基线或消融保留

- Topology-only；
- Temporal-only；
- Deterministic Fusion；
- 不带自监督预训练的 PC-STGR；
- Stage 2 的 P0、P1、P2 概率方法对比。

### 9.3 已从现行方案删除

- 旧版 IC-STGR 主线及其迁移说明；
- 将时序排序、拓扑排序、确定性融合视为并列主方案的旧结构；
- 与当前两阶段框架重复的旧模块编号和兼容层描述；
- 将局部关系重构直接等同于完整故障传播解释的旧表述。

## 10. 阅读摘要

本方案的核心逻辑可以概括为：

> 先利用单个 case 内密集的图结构和自监督信号学习高召回根因候选，再要求每个候选根因在全局约束下生成一张可达、无环、证据可回溯的传播图；最终通过传播解释能力验证并重排根因候选。
