## 2. 必须返修的问题

### R1 [P1] 通用性被误当作论证断裂，削弱了最重要的网络样例

**位置：**主报告 168–169、193、499、552 行；JitterSketch 的 272–273、501–504、511 行；
相关判断同时进入 InArt 分析卡、README、HANDOFF、STATUS 和迁移报告。

InArt 的原文连续写出：Web 应用采用的大模型参数多，分布式训练产生大量传输；
计算加速后通信成为瓶颈；INA 减少送往 PS 的流量；任务扩张后单 PS 入口仍受限；
据此引出多 PS 与路由选择。报告自己的 S5 已承认承接模型规模，却在 168–169 行称两段平行、
作者没有用前段推出后段。依据见 [作者稿 p.1–2](https://www.fangjin.site/pdf/inart.pdf)，
本地 `tmp/www-web-relevance/txt/www24-inart.txt` 第 46、51、53、55、57 行。

**应改为：作者建立了面向 Web 应用组件的技术依赖链；该链也适用于其他分布式训练，
评测未验证具名 Web 服务及服务侧收益。** 后两项限定不能倒推作者没建立联系。
这里复核的是作者怎样论证，不代表已经独立验证其每条背景引用或所有应用主张。

JitterSketch 也不只列应用名：原文从抖动导致接收端缓冲欠载/溢出，接到实时 IFPD 监测与缓冲调整，
再指出高速设备的检测约束；§4.6 用检测结果把有限缓冲分配给抖动流。
见 `www26-jittersketch.txt` 第 32、37、39、363–399 行。
应保留“检测结果支持定向缓冲控制”的桥接与网络侧仿真；继续限定未测具体视频/用户收益。
据此重写横向归纳，不能再把它简化成“只到这类应用会难受”。

**返修要求：**先修作者链条，再修所有摘要副本；替换检查只描述适用范围与改变的条件，
不得把“还适用于别的应用”作为链断的理由。未测服务收益、非 Web 专用、没有实质联系是三个不同结论。

### R2 [P1] 多端点症状没有推出多设备传播，迁移草稿仍把假设写成事实

**位置：**迁移报告 53、60–65、76–81、109–114、202、220、234 行。

单个共享设备或链路故障也可能让多对端点同时异常。探测症状数量不能支持“很少只影响一条链路”，
不能证明设备之间存在多条直接传播关系，更不能由此推出必须采用 DAG。
第 202 行还把 Pingmesh 异常升级为“多个组件间通信同时异常”的已有事实，而服务与端点映射仍未知。
覆盖比例、时间不同步、告警覆盖范围也应分别给出本项目依据；不能以一般遥测特征替代已核实数据事实。

第 109 行要求覆盖统计，111–112 行却说所有补证只需负责人层级描述；部署说明、描述统计和效果实验
是不同材料。说明书不能证明发生率。材料缺失时应采用“可能”并明确待核实，不保留频率断言。

**返修要求：**保留单共同原因这一替代解释。借用已有 Challenge 的问题定义：
相同根或候选根条件下是否仍有不同方向、分支与未决关系需要区分；这些差异如何影响要恢复的事故解释。
把这写成待验证问题，列出所需独立关系标注或实例，不能先把多症状写成传播真值。
业务依赖证据只能补场景联系，不能独自补完图的必要性与贡献。

### R3 [P1] 可追溯性、图准确率与使用者价值被合并成一种评价

**位置：**迁移报告 142、153、174–179、185–188、243 行。

逐边附证据、落在物理拓扑和显式未决关系是可追溯性与合法性要求，不等于关系恢复正确。
同一预测同时报告排名分数和边分数，不能证明指标对应真实任务、图提供增量信息，或工程师受益。
统一评价器是公平比较的实施条件，不是候选链成立的充分条件。
这与 [AGENT 合同](../AGENT.md) 的“有效性诊断不等于图准确率”约定不符。

工程师实验只比较检查集合大小，可能奖励漏查；改用不同案例会引入难度混杂，
笼统写“交叉设计”也未解决次序、学习与经验差异。

**返修要求：**保留独立关系标注下的图质量作为主评价，可追溯性列为辅助维度。
若保留使用者研究，只设计：明确“正确完成任务的前提下，是否减少检查或时间”的假设；
控制输入信息与预测质量，平衡案例难度、顺序和参与者经验；用独立参考答案计任务成功与漏诊。
分别记录事先见过案例、按结果选案例、测试反馈用于调参的边界。此次不运行 T001–T003 或用户实验。

### R6 [P2] Starlink 被强化成了原文没有的普遍前提与反事实结论

**位置：**主报告 396–397、413–415、529 行；HANDOFF 原第 56、63 行；迁移报告 53–54 行。

Intro P1 写缓存靠近用户及按拓扑/地理进行请求映射，没有提出“用户离 PoP 近”这一所有 CDN 技术的必要条件。

**返修要求：**将替换对象和保留/改变的机制逐项写清，不用改变接入技术来判定 Web 关联强弱。
